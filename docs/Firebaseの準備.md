# Firebase の準備（はじめての人向け）

RPM で「スマホとPCで同じ記録を使う」ための準備です。管理者が1回だけ行います。所要時間は20〜30分ほどです。
Firebase の画面は時々変わります。ボタンの名前が少し違うときは、近い名前のものを選んでください。

---

## Firebase とは

Google が提供している、アプリ用の「保管庫」と「受付」のサービスです。RPM では2つの機能だけを使います。

| 機能 | RPM での役割 | たとえると |
|---|---|---|
| **Authentication**（認証） | メールアドレスとパスワードでの登録・ログイン | 受付。本人かどうかを確かめる |
| **Firestore Database**（データベース） | 教材と学習記録を保存する | 一人ずつ鍵のかかったロッカー |

- **料金**: 無料プラン（Spark プラン）で足ります。クレジットカードの登録は不要です。無料の範囲は「1日に読み込み5万回・書き込み2万回、保存1GB」ほどで、事務所内の数十人で使うには十分です。上限を超えても勝手に料金はかからず、その日は止まるだけです。
- **見える人**: Firebase の管理画面に入れる人（管理者）は、全員の学習記録とメールアドレスを見られます。使う人には「管理者は記録を見られる」と伝えておいてください。

---

## 0. 始める前に決めること

**どの Google アカウントで作るか**を決めます。
個人のアカウントで作ると、その人が辞めたときに管理できなくなります。**事務所で共有している Google アカウント**で作るのがおすすめです（あとから管理者を追加することもできます）。

---

## 1. プロジェクトを作る

1. ブラウザで https://console.firebase.google.com/ を開き、決めた Google アカウントでログインします。
2. 「**Firebase プロジェクトを作成**」（または「プロジェクトを追加」）を押します。
3. プロジェクト名に `rpm-study` など分かりやすい名前を入れます（英数字がおすすめ）。規約の確認にチェックして「続行」。
4. 「Gemini in Firebase」を使うかの画面が出たら、オフのままで「続行」。
5. 「Google アナリティクス」は**オフ**にして「プロジェクトを作成」。
6. 「新しいプロジェクトの準備ができました」と出たら「続行」。管理画面（コンソール）が開きます。

---

## 2. ログインの方法を設定する（Authentication）

1. 左のメニューの「**構築**」（Build）→「**Authentication**」を押します。
2. 「**始める**」を押します。
3. 「**ログイン方法**」（Sign-in method）のタブで、「ネイティブのプロバイダ」の中の「**メール / パスワード**」を押します。
4. いちばん上の「**有効にする**」のスイッチだけをオンにします（下の「メールリンク」はオフのまま）。
5. 「**保存**」を押します。「メール / パスワード」の横が「有効」になれば完了です。

### 2-2. 公開ページの場所を許可する

1. 同じ Authentication の画面で「**設定**」（Settings）のタブを押します。
2. 左の「**承認済みドメイン**」（Authorized domains）を押します。
3. 「**ドメインの追加**」を押し、次をそのまま入れて「追加」。
   ```
   takagawa-glitch.github.io
   ```
   （`https://` や `/RPM/` は付けません）

### 2-3. パスワード再設定のメールを日本語にする（任意）

1. Authentication の「**テンプレート**」（Templates）のタブを押します。
2. 「パスワードの再設定」を選び、下の「テンプレートの言語」を「**日本語**」にして保存します。

---

## 3. 記録の保管場所を作る（Firestore Database）

1. 左のメニューの「**構築**」→「**Firestore Database**」を押します。
2. 「**データベースを作成**」を押します。
3. エディションを聞かれたら「**Standard エディション**」を選びます。
4. データベース ID は `(default)` のまま。ロケーション（保存する場所）は「**asia-northeast1 (Tokyo)**」を選びます。
   ⚠ **ロケーションはあとから変えられません。**
5. 「**本番環境モードで開始**」（Start in production mode）を選んで「作成」。

### 3-2. 鍵（ルール）をかける

最初のままだと、だれも読み書きできない状態です。「本人だけが自分の記録を読み書きできる」ルールに変えます。

1. Firestore Database の画面上の「**ルール**」（Rules）タブを押します。
2. 書かれている文字を**すべて消して**、次をそのまま貼り付けます（リポジトリの `firestore.rules` と同じ内容です）。
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /users/{uid}/{collection}/{docId} {
         allow read, write: if request.auth != null && request.auth.uid == uid
           && collection in ['materials', 'goals'];
       }
     }
   }
   ```
3. 「**公開**」（Publish）を押します。

---

## 4. RPM を Firebase に登録して「接続先」をもらう

1. 左上の **歯車のマーク** →「**プロジェクトの設定**」を押します。
2. 「全般」タブを下へスクロールし、「**マイアプリ**」の中の **`</>`**（ウェブ）のマークを押します。
3. アプリのニックネームに `RPM web` と入れます。「Firebase Hosting も設定する」には**チェックしません**。「**アプリを登録**」を押します。
4. 「Firebase SDK の追加」の画面に、次のような部分が表示されます。
   ```
   const firebaseConfig = {
     apiKey: "AIza....",
     authDomain: "rpm-study.firebaseapp.com",
     projectId: "rpm-study",
     storageBucket: "rpm-study.firebasestorage.app",
     messagingSenderId: "1234567890",
     appId: "1:1234567890:web:abcdef..."
   };
   ```
   この `const firebaseConfig = { ... };` の部分をコピーします（`npm install` などほかの説明は無視してかまいません）。
5. 「コンソールに進む」を押して閉じます。
   あとで見たいときは、同じ「プロジェクトの設定」→「マイアプリ」に表示されています。

### この値は人に見せてよいか

`apiKey` は名前に「Key」と付いていますが、パスワードではありません。Web アプリでは利用者のブラウザに必ず配られる「住所」のようなものです。記録を守っているのは、手順 3-2 のルールです。そのため、Claude に貼り付けて渡したり、GitHub に載せたりしても問題ありません。
（ただし、Firebase の画面で「サービスアカウント」の「秘密鍵（JSON ファイル）」を作ることがあれば、それは本物の鍵です。絶対に人に渡したり GitHub に載せたりしないでください。RPM では使いません。）

---

## 5. Claude に渡す

コピーした `firebaseConfig` を Claude Code に貼り付けて、「これを設定して」と伝えてください。`js/firebase-config.js` に入れて GitHub に送ります。数分で公開ページに反映されます。

---

## 6. 動作を確かめる

1. 公開ページ https://takagawa-glitch.github.io/RPM/ を開きます。右上が「**ログイン・同期**」に変わっていれば、つながっています。
2. 「ログイン・同期」→ メールアドレスと6文字以上のパスワードを入れて「**はじめて使う（登録）**」。
3. 教材を1つ登録します。
4. 別の端末（スマホなど）で公開ページを開き、同じメールアドレスで「**ログイン**」。同じ教材が出れば成功です。
5. Firebase の画面の「Authentication」→「ユーザー」に、登録したメールアドレスが出ていることも確かめられます。

## 困ったとき

| 症状 | 原因 | 対処 |
|---|---|---|
| 右上が「バックアップ」のまま | 接続先がまだ設定されていない／反映待ち | 5分ほど待って、ページを開き直す |
| 登録のときに「うまくいきませんでした（auth/unauthorized-domain）」 | 手順 2-2 の承認済みドメインがない | 手順 2-2 をやり直す |
| 登録のときに「auth/operation-not-allowed」 | 手順 2 の「メール / パスワード」が有効になっていない | 手順 2 をやり直す |
| ログインできるが「記録を読み込めませんでした（permission-denied）」 | 手順 3-2 のルールが公開されていない | ルールを貼り直して「公開」 |
| 利用者がパスワードを忘れた | — | 画面の「パスワードを忘れた」からメールで再設定。届かないときは迷惑メールフォルダを確認 |
| 利用者を削除したい | — | Authentication →「ユーザー」で、その人の行の「︙」→「アカウントを削除」 |

## 管理者を追加・交代するとき

歯車 →「**ユーザーと権限**」→「メンバーを追加」で、ほかの Google アカウントを「オーナー」として追加できます。担当が替わるときは、先に新しい人を追加してから外してください。
